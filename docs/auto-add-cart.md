# 自动加车与独立浏览器结账

Apple 购物袋依赖会话。每条任务的加车方式可独立选择「Chrome · 页面模拟」或「API · HTTP 直连」，发售/补货决定何时触发。结账统一进入独立的 Chrome for Testing 配置文件，与日常 Chrome 的购物袋、登录状态和扩展资料分开。

| 加车方式 | 商品入口 | 加车动作 | 成功后的结账 |
| --- | --- | --- | --- |
| Chrome · 页面模拟 | 任务 SKU 对应的官网商品页 | 独立 Chrome 选择配置并点击官网按钮 | 沿用该浏览器会话 |
| Apple 请求 · URL / SKU | 任务 SKU 自动生成的商品页，或同地区的官网商品 URL | Rust HTTP 会话读取商品页和令牌，直接请求官网加车端点 | 把会话交给独立 Chrome 核对购物袋 |

这两个选项与「发售／补货」触发模式分别设置。Apple 请求使用的是官网当前网页的内部请求，并非 Apple 提供稳定承诺的公开 API；如果官网要求等待或验证，发售任务仍需要独立浏览器待命。

1. 在桌面应用的「Profile」页点击「准备独立浏览器」。首次操作会从 Google 官方 Chrome for Testing 下载地址安装当前稳定版到应用的本地数据目录，不改动日常 Chrome。下载完成后再继续。
2. 点击「打开 Profile 编辑器」。应用会用专用配置文件启动 Chrome for Testing，把随应用打包的扩展复制到稳定的本地数据目录，通过浏览器调试协议加载，并直接打开「结账资料设置」，保存取货和配送资料。若扩展未出现，可在 `chrome://extensions` 检查加载状态；如果已有旧版独立 Chrome 正在运行，先关闭它再重试。
3. 在桌面应用中点击「复制扩展连接码」，将连接码保存到**独立浏览器中的扩展**，以便回传支付宝链接。
4. 在「任务」页为目标选择「Restock · 补货」或「Release · 发售」，再选择加车方式，开启「启用自动任务」，然后开始监控。发售模式还要填写开售时间（按电脑本地时区）。新品 SKU 尚未进入离线目录时，可在「监控」页先选门店，再用「手动 SKU」添加目标；任务页可继续填写对应的 Apple 商品 URL。启用自动任务及开始监控时，应用都会检查扩展实际已载入、连接码匹配、取货联系人已启用且姓名、电话、邮箱齐全。预检失败会保留旧设置或阻止监控启动，并在界面显示需修复的项目；修复后重试。

**补货模式**沿用库存事件：确认有货后启动首个命中目标。**发售模式**在设定时间前 10 分钟打开独立浏览器的官方商品页；到开售时间后，在原标签页等待目标 SKU 的加车表单出现。API 模式会先选择官网要求的“不折抵换购”和“不加 AppleCare+”，等官方加车按钮可用后才发出直连请求；页面准备期间不会点击加车按钮。遇到 Apple 等待页或验证页时保留原浏览器会话，验证由你在该页面完成；程序不尝试绕过。开售前返回 404 时，开售后会在原标签页重新请求预热时使用的商品 URL；API 模式填写了自定义 URL 时沿用该地址，最多等待四小时。发售触发不依赖库存接口返回「有货」；库存查询仍照常运行并按真实状态提醒。

每次监控会话最多启动一项购买任务，先到的任务占用执行名额。扩展核对商品 SKU，在 Apple 官方页面选择“不折抵换购”和“不加 AppleCare+”（如页面要求），点击官方“添加到购物袋”按钮；确认购物袋中仅有一件该 SKU 后，记录 Apple 购物袋显示的商品名称供最终订单核对，再点击 Apple 官方结账按钮并选择访客结账。购物袋中有其他商品、数量不是 1 或商品名称无法读取时会停下，供你手动处理。失败时会在页面显示原因。其他命中目标仍会发提醒，但不会连续添加多台设备。暂停再开始监控会重新启用一次加车机会。

**Chrome 加车**使用上述页面操作，旧任务默认沿用这一方式。**API 加车**由 Rust HTTP 客户端建立独立会话，先读取目标商品页和官网的加车信标，再按页面表单提交 SKU、全额付款选项、选购步骤、不折抵换购标志与会话令牌；页面、信标和加车请求分别使用对应的 Chrome 请求头。补货与发售任务都会先读取独立 Chrome 中当前地区的 Apple Cookie，供 HTTP 会话沿用已完成的验证；读取失败时会提示并使用新 HTTP 会话。可填写当前地区 Apple 官网的具体 SKU 商品页，或只到机型的 `/shop/buy-…/机型` 链接；后一种会拼接本任务 SKU 成为具体商品页。留空则通过 `/shop/pdpAddToBag/SKU` 解析。程序只保留商品 URL 的路径，移除粘贴链接中的查询参数和片段，避免预热时意外触发加车；保存 API 任务时立即校验 URL 的地区与 SKU，错误配置不会覆盖原设置。只有 Apple 返回含相同 SKU 的 `step=attach` 成功页，程序才把会话 Cookie 带入独立 Chrome 并打开购物袋；扩展随后核对商品和数量，再继续结账。发售任务仍会提前在独立浏览器打开页面供你完成等待或验证，放行后把该浏览器会话带入直连请求。Apple 的这个 Web 请求不是有稳定版本承诺的公开 API；加车请求一旦发出，遇到 HTTP 错误、连接中断或无法确认成功时都会停止本轮，尽量把同一会话的购物袋交给独立浏览器供你核对，不会重复加车或自动结账。加车前遇到等待页、验证或缺少令牌也会停止，并把 HTTP 会话中适用于商品页的 Apple Cookie 交给独立 Chrome：补货任务打开商品页，发售任务沿用原标签页。你在 Apple 页面完成验证后可重新启动监控，程序不会尝试绕过验证或自动重放刚才的加车请求。2026 年 10 月 16 日的现场验证中，目标 iPhone 18 Pro 和一款 iPhone 17 在独立 HTTP 会话下均于加车请求收到 541；目标商品用 Chrome 官网按钮操作也得到相同错误页。库存接口的“有货”不保证购物袋接受加车。

Chrome 模式点击官网加车按钮前，会用目标 SKU、门店和任务 ID 向桌面应用确认这仍是当前运行的任务。桌面应用尚未记录页面启动时会短暂等待；停止监控或任务被替换后不会继续点击加车。

停止监控、关闭自动任务或从监控列表移除正在执行的商品目标，都会撤销当前任务的自动操作资格；发售待命也会随之退出。API 模式在读取商品页、令牌和发送加车请求前复核任务身份；如果停止发生在加车请求已经发出之后，程序不会继续自动结账，并提示核对独立浏览器的购物袋，因为已发出的请求无法撤销。已经提交的订单仍可回传随后出现的支付宝付款链接。

任务页的「Retry delay」控制任务重试间隔，默认 3000 毫秒，可设置 1000–60000 毫秒；它不改变库存查询间隔。补货任务的浏览器启动失败会在最新库存快照仍有货时按该间隔重试，最多三次；发售任务以该间隔检查等待页是否已放行，打开浏览器失败最多重试三次。成功打开后不再重复开页。监控运行中才启用自动任务时，下一轮仍有货的快照也能启动补货任务。三次都失败时会提示检查浏览器并暂停、重新开始监控；不会因为重试而重复发送到货通知。补货 API 模式若在加车请求前遇到验证、等待页或缺少令牌，会把直连会话交给独立 Chrome 中的同一商品页并停止本轮自动加车；没有可交接的 Cookie 时仍会打开商品页。处理后可重新启动监控。

桌面应用的「自动结账进度」会显示当前目标从打开商品页、进入购物袋、访客结账、填写资料到等待提交订单的阶段。Apple 加车后若直接返回错误页面，扩展会停止并把失败立即回传桌面应用；实测 Apple 对官方加车请求可能返回 HTTP 541，即使商品配置页正常打开也无法加车。Chrome 补货任务遇到 Apple 等待或验证页时会在同一标签页保留任务最多四小时，放行后复核当前任务再点击加车。点击后 30 秒内仍未确认加车会报告失败并提示核对购物袋；若扩展无法回报，后台看门狗会在四小时后停止任务。结账页会定时重试短暂失败的步骤和进度上报；若 Apple 页面或本机桥接持续不可用，进度仍可能停在最后收到的阶段，请查看浏览器页面上的提示。新的监控会话开始时，旧支付宝链接仍标记为「最近收到的」，不要把它当作新订单链接。

扩展会带上监控目标的门店编号和目录中的地区资料，在 Apple 结账页选择到店取货、对应地区与同一家门店，并尝试选择最早可用的取货日期和签到时段，再填写资料并选择支付宝。若 Apple 页面没有显示该门店、地区或时间控件无法识别，扩展会停下并提示手动完成。请核对型号、数量、取货门店、日期与价格。Apple 的隐私同意书、证件后四位和手机短信验证由你在浏览器中自行处理。加入购物袋不锁定库存；Apple 页面或反自动化机制变化时，自动步骤可能失败。

自动继续取货或配送资料页前，扩展会等待已启用的资料填充，并检查可见的必填项；资料缺失时会提示在 Apple 页面补全。
Apple 中国大陆取货页可能要求填写身份证件号码后四位并验证联系人手机号码。这两步须由你在 Apple 页面完成；扩展检测到“验证”按钮时会等待，不会代填证件信息或短信验证码。
遇到隐私同意书、手机验证或未完成的必填资料时，桌面应用会显示等待操作的阶段并发系统提醒；完成后扩展继续尝试进入付款方式。

## 自动填充结账资料

在桌面 Profile 页点击「打开 Profile 编辑器」，或点击**独立浏览器**工具栏的 Apple Bot 扩展图标再打开设置页。可分别保存**到店取货联系人**和**配送收货资料**。此功能与自动加车开关相互独立；只要扩展已启用且在设置页勾选「在 Apple 结账页自动填充」，进入 Apple 结账页就会尝试填入资料。

资料使用扩展的本地存储，留在独立浏览器配置文件内，不写入桌面应用配置、网址或 Git 仓库，也不会通过扩展发往 Discord。资料填充与结账点击只在桌面应用确认当前运行任务后执行；桌面应用重启后，旧标签页的自动操作会暂停。扩展只填用途能够识别的空白字段；原生下拉框只有在保存值与唯一选项精确匹配时才选择。不覆盖已经输入的内容，不填账单、付款卡或发票资料。资料完整时会尝试点击非下单的「继续」按钮；未填上的字段请手动完成，并在下单前核对所有资料。

应用升级或移动安装位置时，桌面应用会沿用独立 Chrome 中原扩展的 ID，保留已保存的 Profile 和连接码。扩展代码按版本复制到本地数据目录，旧副本会保留给仍在运行的浏览器。若已有加车或结账任务在进行，应用会暂时沿用 Chrome 中已加载的可信旧扩展，避免重载时丢失本次任务的浏览器会话；下一项新任务启动时再加载新版。若旧浏览器配置中的扩展身份不一致或有多个候选，应用会提示错误并保留原资料，不会自动创建一个空白 Profile。

桌面应用会将当前任务身份、阶段和最近收到的支付宝链接原子写入应用配置目录中的独立会话文件，文件权限为仅当前用户可读写。应用重启后只恢复一小时内的会话；重启前尚未提交订单的自动操作会暂停，避免旧任务在应用重启后自行下单。若订单已提交且原独立 Chrome 付款标签页和扩展会话仍有效，支付宝链接仍可补报给重启后的应用。过期会话不会恢复。损坏的会话文件会留档并在应用内提示，写盘失败时不会把新任务覆盖到旧任务上。支付宝链接也可能在这一小时内过期，付款前仍须在支付宝页面确认。

## 单笔金额上限与自动提交订单

扩展设置页的「自动提交订单」默认关闭。启用时须填写取货人姓名、电话、邮箱、有效桌面连接码，以及人民币整数的单笔金额上限。扩展在开始结账和准备提交订单时核对桌面应用中的当前监控任务，要求结账流程此前已确认监控门店和支付宝，并在 Apple 最终确认页重新确认仅有一件目标商品和唯一可识别的订单总额。任何一项无法确认或总额超过上限，都会停下供你手动核对。自动点击 Apple 最终下单按钮会生成待付款订单；支付宝付款仍由你本人完成。

## 支付宝链接显示与 Discord 推送

在桌面应用点「复制扩展连接码」，将连接码粘贴到独立浏览器扩展的「结账资料设置」并保存。桌面应用必须保持运行，扩展才能通过本机回环地址把链接送达应用。连接码只保存在应用配置目录和独立浏览器配置文件中；「删除资料和连接码」会清除扩展内的副本。

保存资料后，扩展设置页会检查连接码与桌面应用的本机桥接。请确认页面显示「已连接桌面应用」；若显示连接码不匹配或无法连接，请先修复再开始监控。

Apple 中国区会在提交最终「现在下订单」后跳转支付宝。扩展仅在本次自动加车产生的结账标签页或由它打开的付款标签页中捕获 `*.alipay.com` 页面；若新标签先经过 Apple 商店中转页，扩展会沿用该结账标签页的任务身份。结账时等待 Apple 身份或短信验证，扩展最多保留本次任务身份四小时；订单提交后，付款页可在一小时内追溯同一任务，即使结账或中转标签页已经关闭。桌面应用重启后的会话恢复仍按前述一小时规则处理。若页面暴露 `qr.alipay.com` 二维码目标链接，应用会显示该链接；否则显示支付宝收银台页面地址，并明确标注类型。二维码若在内嵌帧中，扩展也会重试回传；同一任务已收到的二维码不会被顶层页面稍后发出的收银台地址覆盖。链接也会发送到设置中已有的 Discord webhook；同一任务的二维码刷新时，程序会尝试编辑先前发送的 Discord 消息，避免反复发新消息。Discord 明确返回 429 限流时，程序按响应中的等待时间最多重试两次，每次等待不超过 10 秒；若链接已被新任务或新二维码替换，会停止重试。其他发送失败会显示在日志中，应用内已保存的链接不受影响。链接可能过期，付款前请核对商家和金额。扩展不会读取付款密码，也不会代你付款。
