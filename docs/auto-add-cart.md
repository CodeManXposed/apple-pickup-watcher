# 自动加车与独立浏览器结账

Apple 购物袋依赖会话。每条任务的加车方式可独立选择「Chrome · 页面操作」或「API · 直接请求」，发售/补货决定何时触发。结账统一进入独立的 Chrome for Testing 配置文件，与日常 Chrome 的购物袋、登录状态和扩展资料分开。

1. 在桌面应用的「Profile」页点击「准备独立浏览器」。首次操作会从 Google 官方 Chrome for Testing 下载地址安装当前稳定版到应用的本地数据目录，不改动日常 Chrome。下载完成后再继续。
2. 点击「打开 Profile 编辑器」。应用会用专用配置文件启动 Chrome for Testing，把随应用打包的扩展复制到稳定的本地数据目录，通过浏览器调试协议加载，并直接打开「结账资料设置」，保存取货和配送资料。若扩展未出现，可在 `chrome://extensions` 检查加载状态；如果已有旧版独立 Chrome 正在运行，先关闭它再重试。
3. 在桌面应用中点击「复制扩展连接码」，将连接码保存到**独立浏览器中的扩展**，以便回传支付宝链接。
4. 在「任务」页为目标选择「Restock · 补货」或「Release · 发售」，再选择加车方式，开启「启用自动任务」，然后开始监控。发售模式还要填写开售时间（按电脑本地时区）。启用自动任务及开始监控时，应用都会检查扩展实际已载入、连接码匹配、取货联系人已启用且姓名、电话、邮箱齐全。预检失败会保留旧设置或阻止监控启动，并在界面显示需修复的项目；修复后重试。

**补货模式**沿用库存事件：确认有货后启动首个命中目标。**发售模式**在设定时间前 10 分钟打开独立浏览器的官方商品页；到开售时间后，在原标签页等待目标 SKU 的加车表单出现。遇到 Apple 等待页或验证页时保留原浏览器会话，验证由你在该页面完成；程序不尝试绕过。开售前返回 404 时，开售后会在原标签页重新请求商品页，最多等待四小时。发售触发不依赖库存接口返回「有货」；库存查询仍照常运行并按真实状态提醒。

每次监控会话最多启动一项购买任务，先到的任务占用执行名额。扩展核对商品 SKU，在 Apple 官方页面选择“不折抵换购”和“不加 AppleCare+”（如页面要求），点击官方“添加到购物袋”按钮；确认购物袋中仅有一件该 SKU 后，点击 Apple 官方结账按钮并选择访客结账。购物袋中有其他商品或数量不是 1 时会停下，供你手动处理。失败时会在页面显示原因。其他命中目标仍会发提醒，但不会连续添加多台设备。暂停再开始监控会重新启用一次加车机会。

**Chrome 加车**使用上述页面操作，旧任务默认沿用这一方式。**API 加车**由 Rust HTTP 客户端建立独立会话，先读取目标商品页，再向该页当前使用的 `product=SKU&add-to-cart=add-to-cart` Web 请求发起加车。可填写 Apple 官方商品 URL；留空则通过 `/shop/pdpAddToBag/SKU` 解析。只有 Apple 返回含相同 SKU 的 `step=attach` 成功页，程序才把会话 Cookie 带入独立 Chrome 并打开购物袋；扩展随后核对商品和数量，再继续结账。发售任务仍会提前在独立浏览器打开页面供你完成等待或验证，放行后把该浏览器会话带入直连请求。Apple 的这个 Web 请求不是有稳定版本承诺的公开 API；遇到 HTTP 541、等待页或无法确认成功时，任务显示失败，不会误报已加车，也不会跳过验证。

任务页的「Retry delay」控制任务重试间隔，默认 3000 毫秒，可设置 1000–60000 毫秒；它不改变库存查询间隔。补货任务的浏览器启动失败会在最新库存快照仍有货时按该间隔重试，最多三次；发售任务以该间隔检查等待页是否已放行，打开浏览器失败最多重试三次。成功打开后不再重复开页。监控运行中才启用自动任务时，下一轮仍有货的快照也能启动补货任务。三次都失败时会提示检查浏览器并暂停、重新开始监控；不会因为重试而重复发送到货通知。

桌面应用的「自动结账进度」会显示当前目标从打开商品页、进入购物袋、访客结账、填写资料到等待提交订单的阶段。Apple 加车后若直接返回错误页面，扩展会停止并把失败立即回传桌面应用；实测 Apple 对官方加车请求可能返回 HTTP 541，即使商品配置页正常打开也无法加车。商品页打开后 90 秒内仍未确认加入购物袋，也会标记任务失败并在日志提示检查 Apple 页面。结账页会定时重试短暂失败的步骤和进度上报；若 Apple 页面或本机桥接持续不可用，进度仍可能停在最后收到的阶段，请查看浏览器页面上的提示。新的监控会话开始时，旧支付宝链接仍标记为「最近收到的」，不要把它当作新订单链接。

扩展会带上监控目标的门店编号和目录中的地区资料，在 Apple 结账页选择到店取货、对应地区与同一家门店，并尝试选择最早可用的取货日期和签到时段，再填写资料并选择支付宝。若 Apple 页面没有显示该门店、地区或时间控件无法识别，扩展会停下并提示手动完成。请核对型号、数量、取货门店、日期与价格。Apple 的隐私同意书、证件后四位和手机短信验证由你在浏览器中自行处理。加入购物袋不锁定库存；Apple 页面或反自动化机制变化时，自动步骤可能失败。

自动继续取货或配送资料页前，扩展会等待已启用的资料填充，并检查可见的必填项；资料缺失时会提示在 Apple 页面补全。
Apple 中国大陆取货页可能要求填写身份证件号码后四位并验证联系人手机号码。这两步须由你在 Apple 页面完成；扩展检测到“验证”按钮时会等待，不会代填证件信息或短信验证码。
遇到隐私同意书、手机验证或未完成的必填资料时，桌面应用会显示等待操作的阶段并发系统提醒；完成后扩展继续尝试进入付款方式。

## 自动填充结账资料

在桌面 Profile 页点击「打开 Profile 编辑器」，或点击**独立浏览器**工具栏的 Apple Bot 扩展图标再打开设置页。可分别保存**到店取货联系人**和**配送收货资料**。此功能与自动加车开关相互独立；只要扩展已启用且在设置页勾选「在 Apple 结账页自动填充」，进入 Apple 结账页就会尝试填入资料。

资料使用扩展的本地存储，留在独立浏览器配置文件内，不写入桌面应用配置、网址或 Git 仓库，也不会通过扩展发往 Discord。扩展只填用途能够识别的空白字段；原生下拉框只有在保存值与唯一选项精确匹配时才选择。不覆盖已经输入的内容，不填账单、付款卡或发票资料。资料完整时会尝试点击非下单的「继续」按钮；未填上的字段请手动完成，并在下单前核对所有资料。

应用升级或移动安装位置时，桌面应用会沿用独立 Chrome 中原扩展的 ID，保留已保存的 Profile 和连接码。扩展代码按版本复制到本地数据目录，旧副本会保留给仍在运行的浏览器。若旧浏览器配置中的扩展身份不一致或有多个候选，应用会提示错误并保留原资料，不会自动创建一个空白 Profile。

## 单笔金额上限与自动提交订单

扩展设置页的「自动提交订单」默认关闭。启用时须填写取货人姓名、电话、邮箱、有效桌面连接码，以及人民币整数的单笔金额上限。扩展在开始结账和准备提交订单时核对桌面应用中的当前监控任务，要求结账流程此前已确认监控门店和支付宝，并在 Apple 最终确认页重新确认仅有一件目标商品和唯一可识别的订单总额。任何一项无法确认或总额超过上限，都会停下供你手动核对。自动点击 Apple 最终下单按钮会生成待付款订单；支付宝付款仍由你本人完成。

## 支付宝链接显示与 Discord 推送

在桌面应用点「复制扩展连接码」，将连接码粘贴到独立浏览器扩展的「结账资料设置」并保存。桌面应用必须保持运行，扩展才能通过本机回环地址把链接送达应用。连接码只保存在应用配置目录和独立浏览器配置文件中；「删除资料和连接码」会清除扩展内的副本。

保存资料后，扩展设置页会检查连接码与桌面应用的本机桥接。请确认页面显示「已连接桌面应用」；若显示连接码不匹配或无法连接，请先修复再开始监控。

Apple 中国区会在提交最终「现在下订单」后跳转支付宝。扩展仅在本次自动加车产生的结账标签页或由它打开的付款标签页中捕获 `*.alipay.com` 页面；若页面暴露 `qr.alipay.com` 二维码目标链接，应用会显示该链接；否则显示支付宝收银台页面地址，并明确标注类型。二维码若在内嵌帧中，扩展也会重试回传；同一任务已收到的二维码不会被顶层页面稍后发出的收银台地址覆盖。链接也会发送到设置中已有的 Discord webhook；同一任务的二维码刷新时，程序会尝试编辑先前发送的 Discord 消息，避免反复发新消息。链接可能过期，付款前请核对商家和金额。扩展不会读取付款密码，也不会代你付款。
